# 移动开发指南

本文维护导航、状态所有权与协议消费边界。常用命令和高层架构在 [CLAUDE.md](../CLAUDE.md)，项目约束在 [AGENTS.md](../AGENTS.md)，主题和发布分别见 [themes.md](themes.md)、[android-release-guide.md](android-release-guide.md)。源码与测试决定当前实现，历史交接不能替代它们。

## 连接与页面所有权

`AppRoot` 组装主题、安全区、错误边界与独立更新。`WorkspaceScreen` 内的连接根按 workspaceKey 建立 ApiProvider 和业务 Provider；换服释放旧连接状态，切页面、切主题和打开设置不重建连接。

页面使用工作区本地状态，不使用 Expo Router 或 react-navigation：

| 状态/入口 | 职责 |
| --- | --- |
| `messages` /「消息」 | 冷启动直接进入永久 main 主聊天，输入框直接可用，不等待目录 GET；历史失败明确显示错误并锁发送 |
| `news` | 全局新闻阅读列表；文章和来源管理为二级，无底栏 |
| `settings` | 分为助手、资料与任务、信息、应用四组，使用统一卡片列表行；完整外观选择在独立二级页，不在首页平铺。未连接也复用同一布局，需要服务端的入口先引导连接。 |

消息根页顶部是居中的 Pi Muse 悬浮形象岛（`FloatingCompanion`）：64dp 形象与单行省略状态放在不透明语义色圆角表面，带细边框和轻阴影，无标题或独立菜单按钮。形象岛绝对定位在安全区内，聊天列表从完整内容区顶部开始，不预留标题栏或等高 padding；外层 `pointerEvents="box-none"`，仅局部岛面可点击并打开既有主聊天操作面板，岛外仍可滚动聊天。状态继续使用 `mainProgressLabel` 的同一投影，无障碍标签保留完整状态和操作说明；切到新闻或设置时不显示形象岛。`SessionPanel` 是当前执行、审批与历史的信息覆盖层，不是会话目录。专题会话 UI 暂缓，列表/切换面板与新建、改名、删除入口已移除；服务端多会话底座与客户端通用 Store/API 不变，不删除既有会话、历史或工作区。

底栏在三个一级根页且无键盘/覆盖层时显示，main 聊天本身就是消息根页。文章详情、设置子页、浏览器、审批/操作面板和重置确认隐藏底栏。设置与新闻不会挂载另一个聊天；ConversationHost 始终持有 main，只控制可见性，切 Tab 不卸载 SSE/草稿，重置 epoch 与换服保留原生命周期。main 不提供删除入口，重置仍走原确认、审批刷新和未明核对流程。

## 覆盖层、返回与键盘

- 每个原生窗口只由根层 KeyboardAvoidingView 避让：Android 用 height，iOS 用 padding。业务根及连接 Modal 位于 SafeAreaView 内，keyboardVerticalOffset 使用当前 insets.top，对齐相对布局与键盘屏幕坐标；不在 composer 再叠加键盘高度或写死状态栏数值。设置表单可滚动并使用 keyboardShouldPersistTaps="handled"。验收要量实际输入/发送区与 IME 顶边，不以树里存在控件当作未遮挡。
- 原生 Sheet/Modal 隔离背景触控与读屏，并显示在形象岛之上；关闭返回原页面。形象岛顶部位置不随键盘显隐改变，根层仍只避让底部输入区。Back 优先收键盘、关闭浏览器/覆盖层，再逐级退出文章、来源管理和设置子页；新闻讨论进入主聊天后可通过「返回文章」或 Android Back 回原文章。「返回文章」是形象岛下方独立的局部悬浮入口，至少 48dp 命中区，与岛面按实际高度顺排且保留间距，不增加全宽标题栏或聊天留白。正常消息根页 Back 交还系统；点击底部消息明确进入主聊天并清理旧文章来源。
- PageHeader 是通用固定二级标题/返回栏，不随正文滚动。文件目录、详情、完整保存预览、删除确认、未保存草稿与未明锁按 FilesStore 顺序处理，返回不能绕过保护。
- 浏览器是全屏原生 WebView，以同源一次性票据连接后端 Chrome，不注入 API token；关闭不停止后端 Chrome，换服销毁旧状态。

## 协议消费与恢复

修改前核对当前后端 health / serviceVersion、`/docs`、`/openapi.json` 与服务端 contracts，实际消费本模块相关接口。服务端 Web 的 API/聊天聚合可供参考，但不是另一份契约。跨端任务在同一会话内按契约实现，不能沿用永久只读后端的旧分工。

聊天 AG-UI 是执行流；RuntimeProvider 持有一条 `/api/events` 通知流，领域 Store 按失效与重连回读。`conversation_updated` 是历史失效，不是消息正文或系统推送；不因此重挂载聊天、清空草稿或增加第二条通知流。

助手运行进度只集中在消息页形象：形象使用 `mainProgressLabel` 的单一投影（未同步状态 > 未决审批 > 真实运行 > 暂存异常 > 就绪），聊天列表不再渲染独立生成气泡，用户气泡不放逐帧变化的进度文字。送达提示遵循微信式呈现：保存成功与发送中不显示任何标记；失败在气泡左侧显示红色感叹号，未确认显示黄色问号，标记在气泡外侧不占正文空间。首次回复/工具进展时的一次受限历史核对只用于内部保存判定，不渲染成功标记；保存确认与回复成败独立，失败与未明仍走恢复/放弃/重新同步入口，不自动重发，终态后迟到的核对不得污染新代次。

助手形象 `MuseCompanion` 默认使用 `src/companion/builtin-packs.ts` 中的 `builtin:penguin`（冰蓝企鹅，原版 `assets/images/avatar/` 八张 512px 透明图），也接受完整八状态 `images`。`companion-state.ts` 仍从同一运行通知流推导状态（审批 > 工作 > 回复 > 思考；新近终态短暂驱动成功/失败/停止后清除；未同步降灰不猜测运行）。动画用 Reanimated 有限次状态动效表达并在结束后静止（保持无障碍树稳定）；系统减弱动效时保持静态姿态；未接入动作视频，不得把静态图拼接宣称为视频。形象点击仍打开主聊天操作。

`CompanionProvider` 在连接根按 workspaceKey 挂载，断线/已连接页面共享选择，不以形象 key 重建聊天。`CompanionStore` 持有选择、服务端列表、诊断、下载与回退提示；设置 → 助手形象是应用分组的独立二级页，内置包未连接也可使用。独立设备偏好只保存形象 key，不接触连接凭据。`src/api/companion-contracts.ts` 严格解析完整八状态摘要，HTTP 资源通过 Bearer header 下载，不把 token 放入 URL。

缓存由 `companion-cache.ts` 维护：原生使用 `Directory / File / Paths.cache` 下独立 companions 目录，按服务地址隔离、包 ID 和版本组织；Web 使用内存 Blob URI，并在失败/清理时释放 ObjectURL。全部八张 PNG 校验魔数与 786432 字节上限并写入后，才通过 ready 标记原子发布；新版本后台准备，当前可用图保持显示。选择代次、连接代次与 AbortSignal 拒绝迟到结果。同服离线只继续显示完整本地缓存，缺失则提示回退；服务端删除或诊断为不完整也回退内置。换服由 `clearLocalWorkspaceData()` 清理图像缓存并恢复内置选择，不沿用旧服务器形象。系统缓存可能被清理，不把缓存当成服务端安装事实；暂不提供上传 UI。

流式助手 Markdown 经 `src/chat/streaming-markdown.ts` 的纯展示投影：普通文字立即显示，未闭合行内 code/强调/链接等尾部保守缓冲，fence 关闭前缀不先漏出，被截断段落保留换行占位；同一正文在流式、完成与冷启动历史渲染一致，不缓存已撤销内容，替换/缩短立即按当前事实重置。追加导致的末行自然换行不是回排，不使用固定高度或裁剪。

写入不默认幂等。超时、断线或结果未明时保留草稿并锁定重提，先回读实际状态，再按端点所需的明确核对解锁，不自动重发。读取失败保留旧值和错误，不伪装空列表；保存前废弃可能迟到的旧 GET。异步结果始终绑定原连接、Session 与请求资格。

连接页测试是可选探测，保存验证当前草稿后才生效；新密钥重新认证，同址空密钥可沿用已有 token。取消探测不落盘，迟到结果不污染草稿。换服明确确认清理旧本地业务缓存与凭据，不删除远端数据；清理失败保留恢复入口。AccessKey 不持久化。

工具卡、审批与活动仅消费服务端实际投影；批准不等于落盘成功。assistant Markdown 用原生组件呈现，HTML 按字面处理，不加载 Markdown 图片，外链仅允许无凭据 HTTP(S)。用户消息原文不改写。

助手聊天正文通过 `src/chat/chat-visible-text.ts` 的同一可见投影决定气泡有无、渲染内容和复制内容：普通正文中的 `<think>` 块在未闭合时也不显示，分片标签不能先漏出再删除；正式正文继续流式展示，不按“思考”“正在”等词删句子。行内/围栏代码里的字面标签保留。原始历史与工具卡不被改写，文件原文、共享 `MarkdownContent` 和完整修改确认不使用这条聊天清理规则。

## 会话与通知

- 公开 `sessionId` 为 main 或服务端创建的 UUID；`piSessionId` 仅表示底层历史绑定。reset 保留公开 ID，完整历史读取后建立新绑定。聊天所有者以公开 ID + epoch 隔离。
- `SessionStore` 保留通用目录能力，`ChatSessionStore` 保留每会话聊天/设置草稿；当前 UI 只绑定 main，不用目录结果决定聊天是否挂载。目录与正文不复制第二份服务端事实，目录失败也不合成记录。通用创建 API 无客户端幂等键，结果未明锁住再次创建，先回读核对；当前 UI 不提供创建入口。
- `/api/events` 唯一通知流使用 `session_status_updated` / `session_presence_updated`，ready 集合为 sessionStatuses / sessionPresences。`conversation_updated` 只失效指定公开会话；piSessionId 变化也需要回读，不能继续旧上下文。
- 来源元数据仅消费服务端的 featureSource，不从正文猜来源。通知续聊仅 main 引用可追加到用户既有草稿；非 main 引用明确提示暂不可用，不改投 main、不复活或进入专题 UI，也不自动发送。
- subagent 是无独立会话的模型工具，UI 显示“子任务”，协议字段 subagentId / waiting_subagents 保持不变。

## 新闻与短信

- 新闻阅读列表与反馈按钮是兄弟节点。推荐/全部在筛选菜单，收藏独立筛选；来源与抓取在更多菜单。详情为整页视图，顶栏只保留返回，底部固定讨论与喜欢/不喜欢/收藏，未明回读和讨论错误不能藏进菜单。
- 反应互斥、收藏独立，逐篇写入/未明锁共用 newsActionLocked；不喜欢不自动移除文章。客户端无评论 UI、评论写方法、点击统计或兴趣算法，但仍按契约保留历史评论，不迁移或删除服务端数据。
- 全局 NewsPreferencesStore 在连接层保留明确 notes 草稿，只提交可写偏好，不写 learnedNotes。重开/前台读取保留脏草稿，自动读取不解除未明锁，显式核对后才可再保存。
- RSS 来源管理保留添加草稿与删除确认；默认已有来源在前，添加/预设显式展开，抓取与分析状态在后。来源失败与空列表是不同状态。
- SmsProvider 在连接层持有原生权限、监听和 SmsStore；短信页只在可见且前台时进行有界只读刷新，离页/后台停止。静默结果不依赖聊天通知。偏好 API 是专属指令编辑入口，后台规则所有权由当前服务端确定，不在客户端再建标签或规则库；首轮批量导入与后续增量的类型/状态消费当前契约。
- 新闻讨论直接向 main 既有草稿追加标题、限长正文和来源 URL，明确标为不可信外部引用；保留原稿、附件和 pending，用户可编辑后再发送，不弹会话选择器、不调用模型。原文章保持选中以便返回；主聊天维护或重置未明时提示不能追加，不丢草稿。短信只调用全局 `/api/information` 管线。

## 文件与全局整理

FilesStore 持有唯一扁平工作区的目录、原文、草稿与完整前后确认。首次实际修改才建草稿，正文输入节点不重挂载。HTTP 请求与响应均无 scope/owner，仅 path；`shared/` 是普通相对目录，不是第二根。文件详情菜单保留元信息/下载/删除，写入未明只读核对后由用户明确解锁。

审批 preview 只有 workspace/skill 范围与完整 before/after，来源 sessionId/runId 与子任务观察标识保留，不存在文件 owner。批准不等于实际提交成功，不能弱化版本绑定和逐次人工确认。

Dream 全局设置只有 enabled/prompt；游标按来源会话记录，待决建议保留完整正文和 sourceSessionId。应用前确认实际目标，来源已删不能复活；全局资料影响所有会话。run 与待决项写入结果未明先回读并人工解锁，不自动执行第二次。

## 依赖与验证

依赖和 API 先核对当前 manifest 与相应版本文档，不在指南硬编码下一轮升级名单。原生包用 `npx expo install` 解析配套版本，检查 peer 范围，不用 force 或修改第三方包掩盖冲突。CNG 生成的 android/ios 不手工维护；新增 Expo Go 未包含的模块需要开发构建验证。

代码门禁为 lint/typecheck/test；夹具回归不替代当前真实后端、外部模型与 Android 原生链路。真实验收检查当前源码版本、触控、键盘、安全区、前后台与所改恢复场景。主题按其指南覆盖三主题/窄屏；用户可见行为同步中英文手册。文档-only 检查引用、差异与一致性，不启动业务/模型/原生验收。
