# 主题维护

主题功能集中在 `src/theme/`，不依赖服务器、凭据、会话或业务 store。应用根级只有一个 `ThemeProvider`；业务页面只消费语义颜色，不自行推断某套配色。

## 当前主题

| ID | 名称 | 明暗模式 | 说明 |
| --- | --- | --- | --- |
| `classic` | 经典蓝白 | `light` | 原来的白底、冷灰、深色文字与蓝色强调；没有本机偏好时默认使用 |
| `light` | 晨光白 | `light` | 保留暖白、柔和灰绿色表面 |
| `dark` | 深夜黑 | `dark` | 保留当前深色配色 |

经典蓝白恢复原基线的画布、表面、控件、选中态、正文、次级文字、分隔线及头像底色。蓝色和弱文字仅微调深度，使小字及白字按钮达到 4.5 的对比度；不恢复旧布局、旧业务入口或演示数据。

## 修改配色

- 每套配色独立放在 `src/theme/presets/`；改某套颜色只修改对应文件。
- 所有主题必须实现 `types.ts` 的完整 `ThemeColors`，包括悬浮表面填充、细边界和面板遮罩；不得在组件中写固定色值、直接引用某个 preset 或把深色配色当成静态默认值。
- 当前只有聊天页展开的会话面板使用 `src/ui/FrostedSurface.tsx` 真模糊：持续挂载的聊天正文和主导航是 Android `BlurTargetView`，面板在其后作为兄弟层采样；半透明主题遮罩保证内容可读。Android 31 及以上使用 `dimezisBlurViewSdk31Plus`，更低版本按 Expo 模块行为降级为无模糊的着色表面。图标控件和分段导航的半透明填充本身不采样背景；其他页面尚未迁移。
- `blue` 用于按钮和用户气泡，前景用 `onAccent`；小字强调用 `accentText`。状态色分别搭配相应的 `Soft` 背景，不复用动作蓝作为正文。
- 布局、字号、圆角、间距及动效集中在 `src/theme/tokens.ts`，各主题共享。原创 Muse 头像由应用内位图 `assets/images/muse-companion.png` 提供，离线可用。`src/ui/tokens.ts` 只是现有组件的兼容入口，不再含配色或主题逻辑。
- 会话面板动态／审批／历史三项由 `src/ui/SegmentedControl.tsx` 共用整组胶囊：等宽图标与可见文字、选中态、禁用态和 Web 方向键/Home/End 都在控件内。新闻页「推荐／全部」收进紧凑筛选菜单，收藏筛选独立，来源与手动抓取收进更多菜单；各项保留 44dp 命中区和读屏选中语义，不增加第二排横向导航。会话胶囊的单块底板在首次测量和宽度变化时直接定位，后续切换用共享的 200ms 原生位移动画，可中途反向；系统减少动画时直接定位。底板不接收触控或读屏焦点，标签允许随字体缩放自然增高。
- 会话动态、智能体维护独立重置对话框和智能体删除确认的小型文字操作由 `src/ui/ActionButton.tsx` 共用 44dp 命中区、细边界及主／次／危险语义色；风险说明独立显示，确认按钮在窄屏自然换行。目标等页面的筛选使用共享选择外观；列表保留各领域信息层级。三套主题均通过语义颜色绘制选中态、状态与警告。
- 现有页面的文字操作统一使用 `ActionButton`，纯选择使用受控 `ChoiceChip`，表单使用受控 `FormInput`；列表、详情、编辑与确认区共用 `Card`，常规错误、警告和成功提示使用 `FeedbackNotice`。这些控件只管主题外观、命中区和读屏状态，保存资格、审批、结果待核对、草稿与网络请求仍由页面和 store 决定。聊天输入胶囊、审批与文件全文、主题色板及技能开关保留各自必要结构。
- 聊天消息长按继续使用 `src/ui/AnchoredFeedbackMenu.tsx` 的窗口锚定菜单与反应按钮；新闻只复用锚点外观承载筛选与更多菜单，不再以长按呈现文章反馈。安全区定位位于 `src/ui/menu-position.ts`。聊天评论二级界面、复制和写入状态仍由聊天领域组件负责，不受新闻去评论化影响。
- 新闻列表使用主题 `canvas`，无逐篇卡片底色或阴影。列表顶部头像栏与内容区以一条 `line` 细分隔线分层；来源与中文时间在前、标题和最多两行摘要在后，留白与细分隔线区分文章，推荐理由只在详情展示。每篇直接显示喜欢／不喜欢／收藏，反馈行与阅读区为兄弟节点，选中态同时使用图标、文案和主题底色，逐篇写入及未明状态共用串行锁。详情按整页呈现，隐藏头像栏与分隔线，使用紧凑返回／原文／更多顶栏、适中标题与宽行距正文，正文后直接呈现同一反馈行；不提供评论列表、输入框或评论徽标，历史反馈仍按当前服务端契约解析。窄屏操作行允许换行，不设置文章固定宽度。
- RSS 来源管理沿用固定 `AgentHeader`，按阅读器或功能设置的实际入口返回；默认先列订阅，添加表单和中文来源候选显式展开，抓取状态放在列表之后。Dream 先展示智能体选择、最近整理与待决建议，智能体配置和全局提示词默认收起；配置摘要保留未保存提示，展开、收起只改变呈现，不清草稿或解锁操作。两页复用现有主题表面与共享控件，不新增配色或导航体系。
- 目标页使用紧凑工具栏与整组胶囊筛选，卡片突出真实标题、状态和里程碑；三套主题均用语义色显示删除确认、过期数据及结果待核对提示。
- 「全部」视图与私聊共用正常布局中的 `AgentAvatarStrip`：「全部」视图、Muse、新闻、短信、其他智能体，当前头像用主题强调描边和文字区分，不遮住正文。键盘打开时头像缩小、名称收起，正文不再预留旧浮动头像 inset。三套主题共用几何；会话动态面板仍保留完整 `headerHeight` 动画，连接页的 `sessionHeaderBottom` 不变。没有底部 Tab 或独立会话列表。
- 成员消息使用左侧头像列，名称、气泡、工具与终态提示在同一内容列；定向目标与该条消息正文共用行内文本流，不加底色，蓝色用户气泡内沿用白字和中等字重，成员气泡内使用主题强调色，不强制换行；长消息自然折行。Markdown 代码块、表格等保留自身块级结构，不将目标写进代码或表头。同一条回复的群工具默认合为一条低强调的可展开记录，失败数与尚无结果数直接显示；展开后一次展示每项摘要和来源，不嵌套一层层卡片。「全部」视图保留 16 号正文，以 24 行高、横向 14／纵向 10 内边距和 16 消息间距形成阅读节奏；短文本气泡随内容收缩。几何由 `groupAvatar`、`groupMessageRadius`、`groupMessagePaddingHorizontal`、`groupMessagePaddingVertical`、`groupMessageGap` 维护，不改变私聊气泡。功能通知沿用成员消息的同列布局，以低强调的「通知」来源标签和 44dp「由谁承接 · 查看私聊」文字入口区分，不增加大卡片。聊天右上角不放操作。单击头像只切换，已选头像不做额外动作；长按全部进入全局设置，长按智能体进入其设置。添加和删除集中在全局设置的智能体管理。原头像展开式会话面板由智能体设置中的「动态与审批」打开；新闻按本机保存的主视图偏好进入阅读或对话，选择位于新闻智能体设置。

## 增加主题

1. 在 `presets/` 新建仅含 ASCII 字母、数字、连字符、下划线或点的 `.ts` 文件，导出符合 `ThemeDefinition` 的完整定义。
2. 在 `registry.ts` 导入并注册，键与定义内的 `id` 一致。ID 类型、选择器选项、名称、说明及预览自动从注册表生成；无需修改设置页。
3. 更新注册表数量／顺序及颜色基线测试，运行全部测试与真实原生验收。保持所有配色正文和表面对比度门槛。

`id` 是主题身份，`appearance` 只决定明暗行为，两者不可混用：经典蓝白和晨光白均是 `light`。当前快捷切暗目标由 `DARK_THEME_ID` 统一指定。若未来加入多套深色及更复杂的快捷策略，只改主题层，不在页面追加分支。

## 切换与保存

- 主题切换集中在长按「全部」打开的全局设置页直接挂载的 `ThemePicker`，顶栏不再放置显眼的主题切换按钮；原生根页面与独立 Modal 使用 `ThemeStatusBar`。它们都在主题模块内维护。
- `ThemePicker` 将注册表选项放在同一个圆角分组中，使用色板和单选标记表达当前主题；本机恢复、保存和错误提示始终可见。连接页与应用更新 Sheet 也只使用当前主题的语义颜色和共享几何值。
- `useTheme()` 提供当前 `themeId`、完整 `theme`、`appearance`、`colors`、`selectTheme()` 与 `toggleAppearance()`。按主题 ID 判断选中态，不按 `appearance` 判断。
- 亮暗快捷键记住上次选择的浅色方案，因此经典蓝白切暗后切回仍是经典蓝白，不会被晨光白覆盖。
- 本机独立键 `pi-muse-mobile-theme-v1` 只保存版本、主题 ID 及上次浅色主题 ID。原生复用现有 `expo-secure-store`，浏览器调试用独立 localStorage 键；不新增依赖，不复用连接存储，不保存或上报地址、Token、正文。
- 切换立即生效，写盘串行；旧恢复读取和旧写入错误不能覆盖新选择。保存失败保留当前主题并提示，可重新选择同一主题重试。损坏或不认识的偏好安全回到经典蓝白。
- 不按主题更换业务 Provider、面板根层或聊天的 React `key`。面板关闭动画结束前继续遮住聊天与导航；面板打开时聊天仍挂载但不接收触控或读屏焦点。切换不清空连接内存中的会话和草稿；冷启动只恢复主题选择，**不承诺跨进程保存未发送草稿**。
- 会话面板状态胶囊随真实运行同步状态使用语义色；动态区的执行结果来自当前连接，展开式状态说明不替代失同步、失败和待审批的直接提示。
- 不自动跟随系统亮暗，也不加入服务端主题接口。系统减少动画偏好独立保留在 `src/ui/use-reduced-motion.ts`。

## 验证

```sh
npm run typecheck
npm run lint
npm test
E2E_ALLOW_LIVE=1 E2E_API_BASE_URL="http://<真实服务主机>:<端口>" npm run test:e2e:themes
```

最后一项要求已启动最终源码的 Metro8082、已连接 Android 模拟器和同址真实服务的 Expo Go。它会消费一次专用智能体的实际模型聊天，不拦截 HTTP/SSE，不写设备偏好文件、不读取设备凭据。覆盖三套主题、草稿和会话面板保留、真实连接与活动空列表消费、进程重启恢复、320dp 窄屏及无 JS/fatal 错误。通过接口删除本轮专用智能体，保留用户原数据；模拟器尺寸恢复，最后回到主智能体并保留经典蓝白。

真实存储故障仅做本地故障注入测试；不把导出检查当作 iOS、物理设备或独立 APK 的运行验收。
