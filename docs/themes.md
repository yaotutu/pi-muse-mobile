# 主题维护

主题功能集中在 `src/theme/`，不依赖服务器、凭据、会话或业务 store。应用根级只有一个 `ThemeProvider`；业务页面只消费语义颜色，不自行推断某套配色。

## 当前主题

| ID | 名称 | 明暗模式 | 说明 |
| --- | --- | --- | --- |
| `classic` | 经典蓝白 | `light` | 原来的白底、冷灰、深色文字与蓝色强调；没有本机偏好时默认使用 |
| `light` | 晨光白 | `light` | 保留暖白、柔和灰绿色表面 |
| `dark` | 深夜黑 | `dark` | 保留当前深色配色 |

经典蓝白恢复原基线的画布、表面、控件、选中态、正文、次级文字、分隔线及头像底色。蓝色和弱文字仅微调深度，使小字及白字按钮达到 4.5 的对比度；不恢复旧布局、旧业务入口或演示数据。

## 修改配色

- 每套配色独立放在 `src/theme/presets/`；改某套颜色只修改对应文件。
- 所有主题必须实现 `types.ts` 的完整 `ThemeColors`，不得在组件中写固定色值、直接引用某个 preset 或把深色配色当成静态默认值。
- `blue` 用于按钮和用户气泡，前景用 `onAccent`；小字强调用 `accentText`。状态色分别搭配相应的 `Soft` 背景，不复用动作蓝作为正文。
- 布局、字号、圆角、间距及动效集中在 `src/theme/tokens.ts`，各主题共享。原创 Muse 头像由应用内位图 `assets/images/muse-companion.png` 提供，离线可用。`src/ui/tokens.ts` 只是现有组件的兼容入口，不再含配色或主题逻辑。
- 任务页三项胶囊、筛选和列表复用现有共享几何值；任务域紧凑间距留在对应面板内，不改动其他管理页的通用 token。三套主题均通过语义颜色绘制选中态、状态与警告。
- 目标页沿用任务页的紧凑工具栏与整组胶囊筛选，卡片突出真实标题、状态和里程碑；三套主题均用语义色显示删除确认、过期数据及结果待核对提示。
- 聊天顶栏高度、消息间距与内边距、输入区和纯图标底导航使用聊天专用布局值；会话面板头像下方和胶囊下方间距也有专用值。聊天空态只显示一句低对比提示。聊天页四个底部 Tab 的无障碍名称仍保留；收紧首屏不改变连接页的 `sessionHeaderBottom` 或其他管理页布局。三套主题使用同一几何结构。

## 增加主题

1. 在 `presets/` 新建仅含 ASCII 字母、数字、连字符、下划线或点的 `.ts` 文件，导出符合 `ThemeDefinition` 的完整定义。
2. 在 `registry.ts` 导入并注册，键与定义内的 `id` 一致。ID 类型、选择器选项、名称、说明及预览自动从注册表生成；无需修改应用页。
3. 更新注册表数量／顺序及颜色基线测试，运行全部测试与真实原生验收。保持所有配色正文和表面对比度门槛。

`id` 是主题身份，`appearance` 只决定明暗行为，两者不可混用：经典蓝白和晨光白均是 `light`。当前快捷切暗目标由 `DARK_THEME_ID` 统一指定。若未来加入多套深色及更复杂的快捷策略，只改主题层，不在页面追加分支。

## 切换与保存

- 应用页直接挂载 `ThemePicker`，顶栏和会话面板使用 `ThemeToggle`，原生页面与 Modal 使用 `ThemeStatusBar`。它们都在主题模块内维护。
- `useTheme()` 提供当前 `themeId`、完整 `theme`、`appearance`、`colors`、`selectTheme()` 与 `toggleAppearance()`。按主题 ID 判断选中态，不按 `appearance` 判断。
- 亮暗快捷键记住上次选择的浅色方案，因此经典蓝白切暗后切回仍是经典蓝白，不会被晨光白覆盖。
- 本机独立键 `pi-muse-mobile-theme-v1` 只保存版本、主题 ID 及上次浅色主题 ID。原生复用现有 `expo-secure-store`，浏览器调试用独立 localStorage 键；不新增依赖，不复用连接存储，不保存或上报地址、Token、正文。
- 切换立即生效，写盘串行；旧恢复读取和旧写入错误不能覆盖新选择。保存失败保留当前主题并提示，可重新选择同一主题重试。损坏或不认识的偏好安全回到经典蓝白。
- 不按主题更换业务 Provider、Modal 或聊天的 React `key`。切换不清空连接内存中的会话和草稿；冷启动只恢复主题选择，**不承诺跨进程保存未发送草稿**。
- 会话面板状态胶囊随真实运行同步状态使用语义色；动态区的执行结果来自当前连接，展开式状态说明不替代失同步、失败和待审批的直接提示。
- 不自动跟随系统亮暗，也不加入服务端主题接口。系统减少动画偏好独立保留在 `src/ui/use-reduced-motion.ts`。

## 验证

```sh
npm run typecheck
npm run lint
npm test
E2E_ALLOW_LIVE=1 E2E_API_BASE_URL="http://<真实服务主机>:<端口>" npm run test:e2e:themes
```

最后一项要求已启动最终源码的 Metro8082、已连接 Android 模拟器和同址真实服务的 Expo Go。它会消费一次专用空间的实际模型聊天，不拦截 HTTP/SSE，不写设备偏好文件、不读取设备凭据。覆盖三套主题、草稿和会话面板保留、真实连接与活动空列表消费、进程重启恢复、320dp 窄屏及无 JS/fatal 错误。通过接口删除本轮专用空间，保留用户原数据；模拟器尺寸恢复，最后回到主空间并保留经典蓝白。

真实存储故障仅做本地故障注入测试；不把导出检查当作 iOS、物理设备或独立 APK 的运行验收。
