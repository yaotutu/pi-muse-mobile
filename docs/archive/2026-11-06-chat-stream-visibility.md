# 聊天流式正文稳定性排查与修复（2026-11-06）

## 范围

针对用户报告的“正式回复前出现思考/临时文字，随后消失”的问题，核对普通私聊、全部视图、工具调用、Stop 后续发、最终历史回读及复制。只修复已复现的客户端可见文本问题；不把静态猜测或本轮未覆盖的聊天场景判为已修复。

基线为服务端 `7e4a9b8`、客户端 `55bae93`。测试使用当前源码隔离后端、真实外部模型和 Android Expo Go 58.0.5，未使用假模型或拦截业务响应。生产共享 `12330` 保持运行；本次没有服务端业务源码变更。

## 已确认原因

1. 当前真实模型有时把 `<think>…</think>` 写入普通 text，而不是独立 thinking 事件。最初的五个私聊场景中，问候、说明、算术三条带有该标签；时间工具和缺失文件回复没有。没有将所有过程文字都归因于 thinking 事件泄漏。
2. 原 `MessageContent` 只删除已闭合块。真实问候首块为 63 字符，包含未闭合块，原渲染会显示；第二块闭合后，可见内容缩为 57 字符正式回复。数据本身没有被回读清空，是显示投影先漏后删。
3. Android 普通算术聊天已录屏复现：修复前 210 个实际视频帧中，3 帧 OCR 检出可见思考标签，随后消失。原始思考正文不抄入报告。
4. 气泡存在条件及复制此前使用 raw text，而正文有自己的清理：仅改正文仍会留下空气泡，复制也可能带出不显示的内容。本次将三者统一到可见投影，保留原始消息、工具与反馈归属。

## 修改边界

- `src/chat/chat-visible-text.ts`：聊天专用纯函数。未闭合块和分片标签先隐藏，闭合后继续流式显示正式正文；支持多块、大小写、嵌套及代码上下文。
- `MessageContent` 与 `ConversationView.Message` 使用同一投影，气泡有无和复制内容一致。用户原文不处理，工具卡独立保留。
- 普通中文中的“思考”“正在”等词不触发删除；行内/围栏代码里的字面标签保留，覆盖 CRLF 围栏。
- 不改共享 Markdown 阅读器、文件原文、审批全文、后端历史、模型配置或协议，不增加兼容接口、自动重试或新依赖。

| 真实 HTTP / 外部模型 | 初始五类私聊、两类群聊、Stop→新消息、修复后三类私聊；事件与持久化状态核对，不以模型自述通过 |

| 全部视图 | 实际原生输入、发送与后端完成核对，原始回复确实含思考块且算术结果正确；修复后录屏 159 帧，零标签检出。确认单目标回复与最终历史，本轮没有证明群历史存在多 assistant 截断，不因此修改群索引或快照策略 |

补充：视频 OCR 只作为标签可见性的证据，不能单凭“零检出”宣称消除了所有聊天问题。流式前缀断言、真实回读和原生操作共同构成本批证据。

## 保留的失败与未验证范围

- 第一版实现被独立负例检查退回：代码段后接思考块、嵌套块、转义反引号仍泄漏，补回归后修正。初轮全量门禁还发现一个要求旧 `text.replace` 实现的源码断言；改为核对新投影及文件边界后，全量 740 项通过，不用注释伪装旧实现来通过。
- 早期原生驱动被 Expo Go 浮动 Tools 挡住发送，另有录像结束于输入阶段；核对后端没有接纳才重新操作。这些尝试不计入通过。确认过接纳的请求不自动重放。
- 未证实正常私聊在工具阶段会推快照清空正文；实际初始五轮没有发生数据回退。未把另一执行者的此类静态推测记为缺陷。
- 未覆盖所有模型、长历史压缩、全部后台/断网组合、iOS、独立签名 APK；未发布新版本。当前已安装的 v1.0.42 不会因本地源码修复自动更新。
- 本次恢复的是聊天助手正文不显示内部思考的既定边界，不新增用户步骤，故不另写一套产品手册操作；同步内部移动开发指南。

证据保存在本地 `ui-previews/chat-streaming-20261106/`。仅保存合成会话的必要截图/指标；不包含保护配置、真实 Key、鉴权头或用户已有聊天。源码分工为客户端执行者实现，主会话审查、补充负例并完成真实验收。
